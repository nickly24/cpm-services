# Матрица пересчёта тестов

Матрица реализована в `internal/calculate/grading.go:DecideRecalc`. Сохранение изменения создаёт версию и событие Tests; Calculate принимает решение, Tests выбирает подходящие сдачи и создаёт новые задания. Настройка `recalculate_on_test_change` организации должна быть включена в момент сохранения изменения; её значение закреплено в событии.

| Изменение | Пересчёт | Причина |
|---|---|---|
| Удаление вопроса | Да | `question_removed` |
| Изменение типа существующего вопроса | Да; вопрос исключается из старых сдач | `question_type_changed` |
| Изменение веса существующего вопроса | Да | `points_changed` |
| Изменение правильности существующего варианта выбора | Да | `correct_flag_changed` |
| Удаление любого варианта выбора | Да | `option_removed` |
| Удаление допустимого текстового ответа | Да | `text_correct_removed` |
| **Добавление допустимого текстового ответа к существующему вопросу** | **Да; новый случай от 19 октября 2026** | `text_correct_added` |
| Замена допустимого текстового ответа | Да | Удаление и добавление |
| Изменение регистра/пробелов допустимого ответа | Да, как замена исходной строки | Удаление и добавление |
| Перестановка тех же допустимых текстовых ответов | Нет | Набор ключей прежний |
| Название, направление, формулировка, текст варианта, порядок вопросов | Нет | Прежняя политика |
| Добавление вопроса | Нет | Новый вопрос не включается в исторический максимум |
| Добавление варианта выбора, в том числе правильного | Нет | Прежняя политика сохранена |

Если меняется тип вопроса, остальные изменения того же вопроса отдельно не классифицируются. Причины по нескольким вопросам не дублируются. Сравнение допустимых текстовых ключей для определения изменения точное; сама проверка ответа по-прежнему использует Unicode `strip/lower` и полное совпадение с любым допустимым ключом, без частичного совпадения.

Пример нового случая: в ключе «Питер», сохранённый ответ « Москва » давал0. Добавили «Москва», сохранив «Питер»: создаётся пересчёт; сохранённый ответ получает полный вес. «Питер» остаётся верным, «Омск» и пропуск остаются нулевыми. Ответ ученика и исходная версия не переписываются.

## Подразделения и границы

Один общий `test_id` имеет одно содержание и несколько подключений к подразделениям. Подготовка выбирает активные официальные принятые сдачи по `organization_id + test_id`, без фильтра выбранного подразделения. Поэтому изменение общего содержания охватывает подходящие сдачи во всех подразделениях. У каждой сохраняются её `division_id`, `submission_id`, ответы и история; одинаковый ученик в двух подразделениях имеет две независимые сдачи.

Отдельная копия имеет новый `test_id` и не пересчитывается вслед за источником. Чужая организация, тренировки, сброшенные/неактивные и ещё не принятые попытки не входят. Принятые позже времени изменения офлайн-сдачи сохраняют исходную проверку. Исторические исключения типов/вопросов сохраняются.

Обработка асинхронная, по50 сдач за страницу; результаты становятся готовы постепенно. Повтор события идемпотентен, старая версия не заменяет новую. Общий опубликованный рейтинг — отдельный процесс, автоматическую публикацию рейтинга эта матрица не запускает.

## Уже пропущенные изменения

Выпуск нового кода сам по себе не возобновляет события со статусом `skipped/no_scoring_changes` и не изменяет готовые старые результаты. Для них нужна отдельная адресная операция с зафиксированными идентификаторами и новой версией проверки. Повтор старого задания `initial_grade` сохраняет старый ключ и не исправляет этот случай. Конкретная операция восстановления описывается отдельно в локальном release handoff; реальные ID и ответы в этот документ/публичные исходники не включать.
