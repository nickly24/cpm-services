# Интеграция экзаменов: owner → BFF → React UI

Контракт проверен по живому `services/exams` :8010 и исходному коду. Владелец хранит собственные `exams_*_v1` в dev MySQL, проверяет auth и ссылки Core :8011. BFF использует auth/core :8002/:8003 и фиксированный owner :8010. Автоматический перенос экзаменов монолита и нагрузочный SLA не входят в эту проверку.

## Модель и права

Один экзамен организации содержит общие части и вопросы. Подключение сохраняет общий ID и создает отдельные правила, комиссии, назначения, льготы, попытки, результаты и подготовку для подразделения. Полный администратор управляет организацией; сотрудник следует `exams.view/edit`, а импорт также `upload.view/edit`. Экзаменатор видит свои назначения и выполняет устные команды своей комиссии. Ученик читает только опубликованные собственные результаты и доступную подготовку, без чужих голосов и внутренних CAS-полей. Все ссылки на людей используют auth `account_id`.

## Публичный контракт

Owner предоставляет 61 HTTP-операцию, 45 шаблонов путей. BFF дополнительно предоставляет `GET /bff/exams/capabilities` из живого auth-контекста (62 операции). Браузер обращается к `/bff/exams`, BFF меняет только префикс на `/v1/exams`. Все записи требуют UUID `Idempotency-Key`. JSON-правки передают соответствующие версии: `expected_revision`, `expected_state_version`, `expected_result_version` или `expected_history_generation`. Для физического удаления дополнительно требуется `X-Exam-Confirmation`. Импорт загружает multipart поле `file`, до 10 MiB; предел всего запроса owner — 18 MiB. `organization_id` и выбранное подразделение берутся из auth-контекста, не query. Легитимная цель подключения/копирования `division_id` в JSON проверяется owner.

## Проверки и доказательства

`services/bff/scripts/exams_http_test.py` создает свежие `DEV BFF Exams` подразделения, группы, аккаунты и экзамены только через публичные auth/core/BFF API. Он переиспользует публичные сценарии owner HTTP regression, но не запускает его SQL cleanup и 450 повторных чтений. Фикстуры остаются для UI и описываются в приватном `dev/local/bff-exams-demo.json`. Пароли и токены не печатаются.

Живой API прогон прошёл **1275 проверок** (HTTP-статусы, безопасные оболочки и отдельные поведенческие утверждения), run `ff81a02c`. Проверены все 61 публичные операции без сессии и полные реальные сценарии обеих моделей: конфликт голосов, замена, неизменяемый снимок, дополнительные вопросы, апелляция, более плохая завершённая пересдача, удаление истории, глубокие копии и независимые подключения, три XLSX-импорта с правкой/исключением/атомарным commit, подготовка и fingerprint, CRUD ресурсов, CAS/idempotency, org/div/role privacy. Счётчик включает транспортные проверки и не означает 1275 разных пользовательских сценариев.

Реальная доставка Rabbit прошла **25 проверок**: fresh BFF create внешнего экзамена 43 → owner outbox → persistent UUID-сообщение в `cpm.events` / `exams.source.changed` → Rabbit `basic.get` в собственной временной очереди. Сверены `message_id`, schema/producer, exam/org/div IDs, `exam_revision=1`, `source_revision=29` и причина `created`. Очередь удалена в finally; существующие очереди не изменялись, контейнеры не приостанавливались, прямые SQL-записи не выполнялись. Rabbit 4.3 запрещает transient non-exclusive queues: тест использует собственную durable classic queue с TTL/автоистечением и явным удалением. Это проверка публикации owner, а не полного расчёта ratings. Живой `/health/ready` ratings :8012 подтвердил `exams_connected=true`, `exams_mode=required`; внешний компонент tests остаётся в `dev_internal_only`. Существующий ratings не перезапускался.

Владелец исправлен по найденным регрессиям:

- При удалении комиссии ревизия связанного назначения увеличивается; закреплённые состав/имя сохраняются, устаревшая правка возвращает 409.
- HTTP удаления льготы загружает актуальную ссылку ученика; ранее любая такая команда возвращала `student_not_found`.
- Полный администратор может читать закрытый экзамен другого подразделения из каталога организации: общее содержимое доступно, операционные данные отсутствуют до подключения.
- `exam_window` безопасно передаёт даты ученику и назначенному экзаменатору без банка/правил.
- Предпросмотр удаления общего экзамена считает данные всех подключений, без выдуманного срока действия.

React UI проверен **66 браузерными утверждениями**: 36 административных, 17 ученических/подготовки и 13 проведения двумя экзаменаторами. Администратор создаёт/редактирует оба типа, вопросы, правила, комиссии, назначения и льготы; XLSX сохраняет/исключает/применяет строки по UUID; подключение и глубокая копия проверены в отдельных подразделениях. Дополнительно через UI пройдены апелляция 5→3, пересдача с другим составом, сохранение первой оценки до завершения и подтверждённая очистка истории с сохранением первого назначения и льготы. Проверены полный администратор, scoped edit/view, банк и закрытый чужому подразделению каталог организации.

Ученик видит имя конкретного экзамена и направление, действующий нулевой результат пересдачи и первую оценку 4 после апелляции, десятичные внешние баллы и собственный протокол. Неполная сдача не выдаёт оценку. Подготовка проверена до результата и после него: настройки, learned/unmark, изменение fingerprint, потеря успешного ответа и повтор с тем же UUID без двойного счёта, отключение открытой колоды и настроек, собственный прогресс в кабинетах. Исправлен живой баг: owner `training_disabled` с HTTP 409 закрывает открытые карточки/настройки.

Два экзаменатора в независимых сессиях проходят готовность, начало с потерей успешного ответа/явным повтором UUID, замену до голосов, скрытый незакрытый чужой голос, разногласие, повторный раунд и единогласие. Следующий вопрос требует явной команды; пять согласованных обычных ответов публикуют реальную оценку 5. Протокол хранит замену и оба раунда. Активная сдача блокирует смену кабинета, завершённая освобождает её. Desktop и mobile 390px без горизонтального переполнения; JavaScript errors и внешние запросы отсутствуют.

Независимое ревью выявило и исправило коллизию локальных ID: ID попытки/назначения уникален внутри экзамена. BFF-режим UI теперь адресует проведение явной парой `examId + attemptId`; одиночный attemptId отклоняется до запросов владельцу. Журналы ensure/attempt/appeal и React keys включают экзамен и кабинет. Unit regression проверяет одинаковый attemptId в двух экзаменах. OpenAPI сохраняет business path-параметр `division` в DELETE подключения; сборщик и Go regression проверяют все конечные path-параметры и ссылки schemas.

Owner/BFF Go race/vet прошли, весь frontend Vitest — **191 тест в 30 файлах**, TypeScript — 0 ошибок. Затронутые exam/BFF файлы проходят ESLint. Полный проект сохраняет прежние 80 ошибок/22 предупреждения вне этих файлов; это отдельно от сборки.

## Ограничения владельца

Данные старого монолита не мигрированы. Каталог читает агрегаты организации, история и определения сериализуются в одном агрегате; максимум агрегата 40 MiB, живого банка 16 MiB/5000 вопросов. Это не подтверждение 450 одновременно проводимых экзаменов. Рейтинг зависит от собственного сервиса ratings; отсутствие опубликованного результата отличается от оценки ноль. Сотрудник по текущему Core не может состоять в разных организациях; организация переключается только если auth предлагает соответствующее членство.
