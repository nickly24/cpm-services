# Передача сервиса Ratings — 9 октября 2026

Go Ratings и рейтинговый обработчик Go Calculate работают в локальном `cpm_dev`. Реальные Core, Homework, Tests (внутренние и внешние результаты) и Exams подключены; оба режима Ratings — `required`. Рейтинги имеют независимую область `organization_id + division_id`. Формула первого этапа закреплена как `legacy-rating-v1`.

Запрос создаёт долговечное задание. Ratings сохраняет снимок владельцев, персональные входы и outbox; Rabbit передаёт отдельное сообщение каждого ученика в Calculate. Calculate сохраняет результат перед callback, Ratings постепенно увеличивает `processed_count`. Полный рейтинг публикуется атомарно после завершения всех участников. Во время расчёта остаётся доступной предыдущая полная версия; история неизменяема. Отмена, повтор и запоздалые callbacks проверяют ID задания, область, ревизию и хеш входа.

## Изменения аудита

- Внешние Tests требуют явный scoped `external_domain:{schema_version:1,status:"ready",organization_id,division_id}`. Реально подключённый пустой каталог даёт пустой массив и устойчивую версию; отсутствующий/неготовый домен удерживает job в ожидании, ошибочный контракт запрещает публикацию. Pending внутреннего теста также не превращается в ноль.
- Новые детали тестов содержат `calculation_status:ready|missing`: завершённый ноль отличим от отсутствующего результата. Числовой вклад отсутствующего результата остаётся 0. Поле опционально для сохранённой истории.
- Homework проверяет даты, идентичности и конечные числа. ОВ учитывается только после своего дедлайна по московскому календарю; следующий календарный переход рассчитан точно. Период включает обе даты, максимум 366 календарных дат.
- Математика сверена с настоящими legacy-функциями на наблюдаемом dev CPython 3.12.14. Компенсированное суммирование тестов/экзаменов и отдельные промежуточные операции сохраняют его IEEE-754 результат; четыре golden-вектора проверяют дробные оценки. Код не округляет итог и не перераспределяет веса.
- Постоянный consumer `exams.source.changed` принимает durable quorum queue `cpm.ratings.exams-source.v1`. Миграция `003_source_events.sql` добавляет собственный inbox и scoped high watermark. Commit предшествует ACK; точный повтор безопасен, запоздавшая версия не откатывает счётчик, конфликт UUID/неподдерживаемый контракт уходит в DLQ.
- Event watermark помечает прежнюю публикацию устаревшей и блокирует публикацию более старого снимка. События не создают автоматических заданий. Для сравнения применяется `source_revision`, а не техническая `exam_revision` конверта. Оценку действующей попытки и апелляции выбирает Exams.
- Перед переключением публикации календарная граница проверяется повторно после SQL-блокировок: ожидание до полуночи или начала экзамена не позволяет опубликовать уже истёкший снимок.
- Вложенные результаты Calculate проверяются по фактическому DTO: объекты деталей, обязательные конечные оценки и значения `tests.directions`, идентичности, статусы и nullable metadata. Повреждённый callback получает `400 incomplete_rating_result`, повреждённая сохранённая версия — `503`. Исторический тестовый `calculation_status` может отсутствовать; данные и хеш не переписываются, формула повторно не вычисляется.

## Подключение BFF и повторный запуск

HTTP Ratings: `127.0.0.1:8012`, контракт `GET /openapi.json`; публичные методы, состояния и ошибки описаны в [README](../README.md). Создание/retry/cancel требует `ratings.edit`, журнал/версии/отчёт — `ratings.view` в выбранной области. Student получает свою строку, proctor — участников своей текущей группы. `freshness` — диагностика источников, не изменение сохранённых оценок. Повтор создаёт новую ревизию и входы; старую публикацию не редактирует.

Для текущего локального runtime применены миграции `001`, `002`, `003`; два новых имени таблиц внесены в dev extensions manifest. Целевые команды `./dev/ratings start-ratings`, `offline-ratings-up`, `offline-calculate-up` затрагивают соответствующий сервис. Общие `integration-up` команды требуют координации с владельцами.

## Передача отдельным UI QA-чатам

На 20:41 МСК 9 октября Docker inspect подтверждает оба указанных running/healthy образа без последующего рестарта. Контрольный SHA-256 исходников Ratings — `382bcf142b13750283832a78b864a546ac41cd2fbf60571da03d45d3176adcfc`: 30 файлов `*.go`, `go.mod`, `go.sum`, `migrations/*.sql`, отсортированных по относительному пути; хешируется `path + NUL + bytes + NUL` для каждого. Это идентификатор прочитанного дерева, а не заявление об отдельной новой сборке.

Остатков реализации в области Ratings нет, новые jobs, fixtures и fault-прогоны не запущены. Отдельная UI-приёмка ещё не проведена этим чатом: перечисленные выше результаты — owner HTTP/queue/recovery/unit, они не заменяют свежие действия в UI. Общий QA RELEASE даёт координатор по [плану](../../../outputs/microservices/ui-qa-coordination.md); подготовка матриц не является разрешением запускать UI/HTTP сценарии.

Для чтения существующих примеров доступны собственные tenant scopes: A1 `1001/10188`, A2 `1001/10189`, B1 `2001/10190`, B2 `2001/10191`; private manifest `dev/local/ratings-tenant-10d3deb9e73c-fixtures.json` содержит логины и credentials. Его нельзя публиковать или изменять чужим QA-набором. Последняя собственная публикация B2 — `2c3ae817-0008-4c39-8a40-68de64dcf8a4`, revision8, два ученика, итог 46,5 и 0; A1 — `5b6e726d-76d0-44a2-adcc-9d12fd6a949e`, итог первого ученика65. Последующие законные изменения общего каталога Core могут сделать эти версии устаревшими, сохраняя оценки и историю. QA создаёт собственные UI fixtures только после общего release.

Background apply Uploads и новая Auth grant принадлежат другим владельцам и не подтверждены результатами Ratings. Их pending/blocked состояние не считается завершённым импортом. Новых рестартов Ratings/Calculate или повторов старых suites со стороны этого чата не планируется; найденные QA дефекты должны возвращаться первичному владельцу для исправления и свежего UI retest.

Новые чистые tenant → period → lifecycle сценарии выполняются последовательно с готовыми владельцами и стабильным каталогом направлений. Core консервативно включает весь каталог направлений организации в snapshot hash: добавление другого направления может пометить сохранённые рейтинги этой организации устаревшими. Это не меняет исторические строки. Tests external применяет HTTP hash/revision contract; новый orphan outbox не создавался.

Проверено локальное развёртывание на синтетических данных. Production не открывался; нагрузка на 450 одновременно сдающих не измерялась. `as_of` фиксирует время задания и календарную логику, но не восстанавливает прошлое состояние оценок. Владельцы читаются независимо: общей распределённой транзакции между сервисами нет. Событийный fence защищает от уже сохранённой новой Exams revision, а owner hash/read freshness сохраняют диагностику последующих изменений.
