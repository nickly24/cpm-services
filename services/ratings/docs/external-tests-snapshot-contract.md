# Внешние тесты в рейтинге

Владелец каталога и подтверждённых предметных результатов — Go tests. Ratings
получает их через `POST /internal/tests/ratings/snapshot` с `X-Service-Key`.
Контракт запроса остаётся `{organization_id, division_id, date_from, date_to,
as_of}`. Tests проверяет организацию, подразделение и направления через core.
Этот снимок не читает legacy MySQL или production.

Ответ `data` включает внутренние `tests`, внешние `external_tests`, общий
`input_hash`, `external_domain:{schema_version:1,status:"ready",organization_id,division_id}`
и `external_source_version` — SHA-256 упорядоченного внешнего
каталога с результатами и ревизиями. Пустой подключённый источник — `[]` с
версией; отсутствие источника не равно пустому массиву.

Перед чтением внешнего каталога tests проверяет durable marker в своей
`tests_external_domain_v1`: `_id:"external-tests"`, `schema_version:1`,
`status:"ready"`. Владелец создаёт его после инициализации предметных коллекций
и индексов. Отсутствующий, неготовый или повреждённый marker возвращает
`503 external_domain_unavailable`; успешный снимок и его версии не публикуются.
Сам по себе пустой Mongo cursor или SHA-256 пустого массива не подтверждает
готовность бизнес-домена. Старый executable без explicit `external_domain`
отклоняется с `external_tests_not_connected`; задание ожидает источник и может
быть отменено. Здоровый и явно подключённый пустой каталог допустим.

Внешний элемент использует согласованный DTO теста: `test_id`, `title`,
`direction_id`, `direction_name`, `start_at`, `published`, `is_archived`,
`source_revision`, `results`. Внешний тест принадлежит одному подразделению;
копия в другом подразделении самостоятельна и имеет другой ID. В выборку входят
только неудалённые тесты выбранного подразделения. Дата теста выбирается по включительному
московскому календарному периоду и сериализуется как московская полночь в UTC.
`as_of` не ограничивает тесты с будущей датой внутри выбранного периода — это
поведение старой формулы.

Результат содержит `account_id` из auth, стабильный предметный `submission_id`,
`calculation_revision` результата, `calculation_status` и `score`. Legacy
student profile ID не заменяет account ID. Числовой результат в диапазоне
0..100, включая дробный и явный `0`, имеет `ready`. Записанное неизвестное
значение сохраняет идентичность результата и имеет `missing`, `score:null`.
Отсутствие предметного результата представлено отсутствием строки, а не
синтетической записью с нулём. В индивидуальном расчёте оба случая дают ноль по
старому правилу пропуска; в исходном снимке и его версии они различаются.

Ratings передаёт calculate персональные тесты с `source:"external"`.
Идентичность внутреннего и внешнего теста разделена этим полем. Формула
`legacy-rating-v1` остаётся прежней: сначала среднее всех внутренних и внешних
тестов по нормализованному названию направления, затем среднее направлений.
Направления без тестов периода не добавляются. Итоговые веса не меняются:
домашние работы ×0.25, экзамены ×6, тестовый компонент ×0.45.

Tests читает полный источник дважды и возвращает 409 при изменении хеша между
чтениями. Общий хеш включает внешнюю версию, ревизию каталога и ревизии
результатов. Даже замена оценки на то же число с новой ревизией меняет версию.
Ratings сверяет источники перед публикацией и при запросе актуальности;
изменение, удаление или недоступность источника делают прежний опубликованный
рейтинг устаревшим. Историческая версия сохраняется, автоматической подмены
отсутствующего источника нулевыми оценками нет.

В режиме `required` ratings требует явный readiness DTO версии1 для точного org/div,
массив и корректную версию, проверяет
диапазон, дату, направление, ревизии, отсутствие дублей и согласованность
`ready`/`missing` со значением. Общие ограничения снимка: 1000 внутренних и
внешних тестов суммарно, 2000 различных аккаунтов, 100000 результатов и 16 MiB
у владельца. Ошибка чтения внешнего домена прерывает весь снимок.
