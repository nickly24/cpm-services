# HTTP-проверка изоляции организаций и подразделений

`scripts/tenant_test.py` создаёт самостоятельные синтетические данные в локальном `cpm_dev`. Он использует только HTTP API владельцев данных, без SQL, Mongo, управления RabbitMQ или перезапуска сервисов. Это отдельный сценарий от исторического `http_test.py`, который содержит временную Mongo-подмену.

## Предусловия

Нужны работающие auth `8002`, core `8003`, tests `8004`, calculate `8005`, homework `8006`, exams `8010`, ratings `8012` на `127.0.0.1`. Ratings должен работать с `RATINGS_EXAMS_MODE=required` и `RATINGS_EXTERNAL_TESTS_MODE=required`. Проверка заранее читает снимок tests и требует `external_domain.status=ready`, явный массив `external_tests` и версию источника. Отсутствующий или неинициализированный источник не пропускается.

Скрипт читает закрытые настройки `dev/.env` через существующий `bootstrap.settings()` и пароль синтетических аккаунтов из `dev/local/accounts.json`. Эта проверка ограничивает имя баз `cpm_dev` и выделенные локальные порты. Адреса HTTP фиксированы в скрипте, перенаправления запрещены. Production-конфигурация не читается.

Используются две уже созданные dev-организации `1001` и `2001` и их администраторы `dev_admin`, `dev_admin_math`. Публичного API создания организации сейчас нет. В каждой организации создаются собственные школа, направление и два новых подразделения. В каждом подразделении создаются две группы и два участия учеников, собственные домашка ОВ, официальный тест, внешний тест и внешний экзамен. Новый ученик A получает два участия A1/A2; его оценки в этих областях различны.

Публичный grant Core разрешает назначение нового аккаунта только внутри его организации-владельца. Поэтому межорганизационное переключение проверяется на уже существующем синтетическом `dev_student_01`, который имеет участия в `1001/1001`, `1001/1002`, `2001/2001`. Его данные и права не меняются; переключается только созданная скриптом сессия.

## Сценарии

| Область | Проверка |
|---|---|
| Полная цепочка | Четыре задания → RabbitMQ → durable inbox calculate → callback → полная публикация. Ручная формула и ID источников совпадают только со своим подразделением. |
| Идемпотентность | Один ключ даёт четыре независимых задания в четырёх областях; повтор внутри области возвращает прежнее задание. |
| Полный администратор | Доступ к другому своему подразделению разрешён; чужая организация, её job/version/account ID, cancel/retry и отчёт недоступны. |
| Делегированный администратор | Видны только выбранное участие, свои строки, поиск и отчёт. Чужие подразделение и организация не открываются даже при наличии другого участия. |
| Отзыв прав | Новая собственная роль меняется с edit на view, затем без ratings. Старый токен сразу теряет запись, затем чтение, историю, задания и экспорт. Роль восстанавливается, включая обработку ошибки. |
| Студент | `/ratings` и `total` содержат только себя, `/me` соответствует своему участию; чужой account, jobs/versions/report и создание задания запрещены. |
| Проктор | Строки и `total` ограничены текущей группой; чужой ученик и полный отчёт недоступны. |
| Контекст кабинета | A1 ↔ A2 и существующие участия двух организаций сохраняют account ID; все заменённые поколения токена отклоняются. |
| Callback | Bearer не заменяет сервисный ключ. Подмена org/div/job/revision/account/hash и чужой путь отклоняются. Другой результат даёт конфликт, точный повтор сохраняет progress и обе публикации. |
| Постоянные метки участия | Удаление обоих собственных участий ученика с опубликованными рейтингами возвращает `409 rating_exists`; участия, группы, снимки Core и обе публикации сохраняются. При неожиданном принятии удаления собственное участие и исходная группа восстанавливаются перед завершением с ошибкой. |

Для экспорта используется текущий `/report`: это JSON с полным выбранным периодом и деталями, из которого клиент формирует файл. Отдельного серверного XLSX API ratings сейчас нет. Проверка не заявляет проверку несуществующего маршрута.

Ожидаемые ненулевые итоги: A1 = 75.5; общий ученик A2 = 35; второй ученик A2 = 100; B1 = 43; B2 = 46.5. В остальных местах публикуется настоящий ноль. Официальный и внешний тесты одного направления усредняются; баллы внешнего экзамена `923.45` не подменяют его оценку в формуле.

## Запуск и результат

Запуск выполняется после согласованного обновления локальных сервисов:

```sh
dev/.venv/bin/python services/ratings/scripts/tenant_test.py --allow-fixtures
```

Каждый запуск создаёт свежие области. Опубликованная история и постоянные метки участия сохраняются. Скрипт завершает только собственные сессии и не удаляет фикстуры. Частично созданные фикстуры также сохраняются для диагностики.

`dev/local/ratings-tenant-report.json` содержит результат, количество проверок, сценарии, прогресс заданий и синтетические ID, без паролей и токенов. Собственный manifest `dev/local/ratings-tenant-<run_id>-fixtures.json` содержит пароль новых тестовых аккаунтов и хранится с режимом `0600`; его нельзя публиковать. Сам скрипт выводит только статус, счётчик и `run_id`.

Синтаксическая проверка и `--help` не выполняют HTTP и не создают данные. Подготовленный сценарий сам по себе не является доказательством успешного живого запуска; для этого нужен отчёт со `status=passed`.

## Живой результат 2026-10-09

Запуск `10d3deb9e73c` завершился с `status=passed`: 508 HTTP и содержательных проверок. Оба источника работали в `required`. A1/A2 — собственные новые подразделения `10188`/`10189` организации `1001`; B1/B2 — `10190`/`10191` организации `2001`.

Во всех четырёх областях сначала подтверждены действительно пустые и готовые каталоги владельцев. После создания источников четыре задания полностью опубликованы для двух участников каждое; durable inbox calculate содержит ровно две готовые доставки с правильными org/div/job/revision/account. Проверены ручные итоги 75.5, 35, 100, 43 и 46.5 и отсутствие чужих ID источников в деталях.

Чужие организации, подразделения, задания, версии, аккаунты и отчёты отклонены; действующие токены сразу соблюдали смену роли. Старые поколения токена после переключения кабинета остались отозванными. Отказ удалить оба участия общего ученика вернул точный `409 rating_exists` и сохранил участия, группы, снимки Core и публикации. Подменённые callback отклонены, точный повтор не увеличил progress. Собственная роль восстановлена, собственные сессии закрыты, история сохранена. SQL, Mongo, администрирование RabbitMQ и перезапуск сервисов не использовались.

Закрытый manifest: `dev/local/ratings-tenant-10d3deb9e73c-fixtures.json`. Проверена полнота полей для последующих проверок периода и жизненного цикла, отсутствие токенов в полях участников и режим `0600` обоих файлов. Этот результат подтверждает изоляцию и расчёт на указанных синтетических данных; он не является нагрузочным тестом или проверкой production.
