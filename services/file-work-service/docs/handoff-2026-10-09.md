# Worker monitoring handoff — 2026-10-09

Implemented only inside `services/file-work-service`; no shared container restart or other service/configuration change.

- Heartbeat: immediate and every 10s, `POST /internal/homework/file-work/heartbeat`, existing `X-Service-Key`, hard 3s deadline, no redirects. Accepted means HTTP 200 and exactly `{"status":true}`.
- DTO: `schema_version:1`, fresh per-start UUID `instance_id`, UTC `observed_at`, bool `rabbitmq`/`tools`/`processing`, `storage:{state:"unknown"|"ok"|"error",checked_at:UTC|null}`. It contains no business/object/credential metadata.
- S3: independent immediate/30s Put/Get/Delete probe, exact key `file-work-health/{instance_id}/probe`, unique tiny synthetic bytes, bounded exact readback, version-aware Get/Delete. Five seconds for Put/Get and three for independent cleanup, including ambiguous writes and read failures. Completion sets `checked_at`; any failure is `error`.
- Readiness: `/readyz` is 200 only for Rabbit/tools ready, successful storage <=60s, accepted heartbeat <=30s; otherwise 503 with safe component details. `/healthz` remains process liveness. Unknown storage and missing heartbeats cannot pass readiness.
- Processing uses an atomic flag only; Rabbit topology, consumer/reconnect, claims, retries, and ACK rules retain their existing behavior.
