# Кеш Tests и каталог с доступностью

## Контракт для BFF

`GET /v1/tests/divisions/{division}/catalog-with-access`

Авторизация: обычный `Authorization: Bearer …`; Auth заново проверяет пользователя на каждом запросе. Core заново проверяет выбранное подразделение. Доступ имеют студенты выбранного подразделения и администраторы с `tests.view`. Для студента выдаются только опубликованные неархивные тесты этого подразделения.

Параметры совпадают с `GET /v1/tests/divisions/{division}/tests`: `q`, `direction_id`, `owner_division_id`, `relation=all|owned|attached|copy`, `is_archived`, `limit=1..100` (по умолчанию 20), `offset=0..100000` (по умолчанию 0). `is_archived=true` для студента возвращает 403. Объём и порядок страницы, фильтры и общее число записей имеют прежнюю семантику.

Ответ: `{"status":true,"data":{"items":[…],"total":42,"limit":20,"offset":0}}`. Каждая запись — **плоский существующий `TestView`**, дополненный полем `access`; дополнительной вложенности `test` нет. Тип Go: `TestWithAccessView { TestView; Access AccessView }`. В BFF достаточно расширить прежний тип строки каталога полем `access` и отказаться от отдельных GET `/tests/{test}/access` для каждой карточки.

Пример дополнительного поля (остальные поля записи остаются прежними):

```json
{
  "id": "670000000000000000000001",
  "revision": 4,
  "title": "Тест",
  "access": {
    "test_id": "670000000000000000000001",
    "division_id": 11,
    "revision": 4,
    "official_access_allowed": false,
    "review_access_allowed": false,
    "official_reason": "already_submitted",
    "review_reason": "calculation_pending",
    "scope": "test_content_and_attempt",
    "attempt_state_checked": true,
    "content_checked": true,
    "server_time": "2026-10-09T10:00:00Z",
    "practice_access_allowed": true,
    "practice_reason": "allowed",
    "attempt_id": "670000000000000000000002",
    "submission_id": "670000000000000000000003",
    "calculation_status": "queued"
  }
}
```

`attempt_id` и `submission_id` допускают `null`; `calculation_status` без сдачи равен пустой строке. Для администратора доступность отражает настройки и наличие вопросов, как прежний отдельный `/access`; сдачи других людей в каталог не подмешиваются, поля идентификаторов равны `null`, `practice_reason` и `calculation_status` пустые. Данные вопросов, правильные ответы, ответы студента и оценки в этот DTO не входят.

`access` строится тем же чистым методом, что и отдельный `/access`. Сохраняются текущие условия: расписание и публикация, архив теста/направления, пустой тест, возобновление существующей попытки до её собственных дедлайнов, ожидание офлайн-загрузки, уже принятая сдача, ожидание расчёта, просмотр после готового расчёта и условия тренировки. Один момент `server_time` используется для всех записей страницы.

Внутри одного запроса подразделения-владельцы загружаются одним обращением Core, направления — по одному обращению на уникальное направление, попытки студента — одним запросом Mongo по `organization_id + division_id + account_id + test_id in page + practice=false + active=true`. Направления и владельцы переиспользуются только внутри запроса. Состояние попыток берётся заново при каждом запросе; большие ответы, коммиты и результаты не загружаются.

## Кеш данных

Кеш находится в памяти одного `Store`, ограничен одновременно 1024 записями и 64 MiB сериализованных данных. Одна запись не превышает 2 MiB. При заполнении вытесняются давно неиспользованные записи. Возвращаемые значения восстанавливаются из сериализации, поэтому изменения массивов, карт или истории вызывающим кодом не меняют кеш.

| Данные | Ключ | TTL | Проверка перед выдачей |
|---|---|---|---|
| Полный документ теста | организация + test ID + revision | 20 секунд | Живой Mongo GET с проекцией ID, организации и revision |
| Страница каталога | организация + полный фильтр, включая подразделение + offset + limit | 20 секунд | Живой Mongo запрос тех же ID/revision в том же порядке страницы |
| Неизменяемая версия содержимого | организация + content version ID | 1 час | Версия неизменяема; полномочия вызывающего процесса проверяются отдельно |
| Очищенные вопросы для студента | организация + content version ID | 1 час | Только явный DTO `StudentQuestion`, без ключей правильности и истории |

В холодном кеше документ или каталог выполняет дополнительную небольшую проверку ревизий перед полным чтением. В тёплом кеше тело вопросов и история из Mongo повторно не передаются, но проверка актуальности остаётся обязательной. Ошибка Mongo или исчезновение документа закрывает запрос даже при наличии тёплого кеша. Документы с отсутствующей/нулевой ревизией не кешируются. Пустая страница может кешироваться, но её состав также сверяется заново.

После успешных `Insert`, `Save` и `EnqueueSave` инвалидируются все ревизии изменённого документа и все страницы его организации. При конфликте CAS они также инвалидируются. Счётчик поколения запрещает запоздалому чтению, начавшемуся до инвалидации, вернуть старые данные в кеш. Версии содержимого остаются в кеше: редактирование создаёт новый version ID, не меняя прежнюю версию. Изменения на другом экземпляре сервиса становятся видимы благодаря живой проверке ревизии и состава страницы; отдельного распределённого канала инвалидации не требуется.

Не кешируются: токены, роли, полномочия, ответы Core между запросами, попытки, сдачи, баллы, агрегаты и снимки рейтинга. Источник `mongoRatingSource` продолжает напрямую читать Mongo и сравнивать два полных расчётных снимка. Этот кеш не участвует в выборе актуальной версии расчёта или записи результата.

## Отличия от старого кода

В `cpm-back-main/cpm_back/services/exam/exam_memory_cache.py` были отдельные кеши документа и очищенных вопросов на 600 секунд, облегчённого списка опубликованных тестов на 15–30 секунд и направлений на 300 секунд. `test_versions.py` кешировал неизменяемые версии и очищенные вопросы с копированием данных. В Tests сохранена польза кеша неизменяемых версий, но добавлены ограничение памяти, изоляция организаций, учёт подразделения/фильтров, CAS-инвалидация и обязательная живая проверка изменяемых данных. Межзапросный кеш направлений перенесён только в запрос: переименование и архивирование в Core должны быть видимы сразу.

## Подключение маршрута

Маршрут подключён в `specs()` через `s.catalogAccessSpec()`, параметры каталога представлены в OpenAPI для `/catalog-with-access`. Подключение в BFF/UI принадлежит владельцу BFF и выполняется по этому контракту.
