# Tests: внешний каталог и импорты

Внешний тест означает работу, выполненную вне CPM. Владелец Tests хранит название, направление, дату и результаты. У этой сущности нет вопросов, локальной попытки, URL прохождения или тренировочного режима. Один документ относится к одной организации и одному подразделению; внешний результат не переносится между подразделениями автоматически.

## Область и права

Все публичные внешние маршруты начинаются с `/v1/tests/divisions/{division}`. Подразделение сверяется с живым Auth/Core контекстом и принадлежностью документа. Полный администратор управляет своей организацией; сотрудник и ученик работают в выбранном разрешённом кабинете. `account_id` — идентификатор аккаунта Auth, `student_id` — профиль ученика Core. Они не взаимозаменяемы.

Каталог доступен ученику, `tests.view`, `test-results.view` или `upload.view`. Создание и изменение реквизитов требуют `tests.edit`. Чужие оценки требуют `test-results.view`; коррекции — `test-results.edit`. Ученик всегда получает только собственный результат, даже при явном фильтре `account_id`. Удаление теста с результатами дополнительно требует `test-results.edit`. История реквизитов доступна редакторам каталога, но изменения оценок скрыты без права просмотра результатов.

Канонический ключ прав — `test-results`, старый `test_results` используется лишь при отсутствии канонического ключа. Отозванное каноническое разрешение нельзя восстановить старым alias.

## HTTP

| Метод | Хвост после `/v1/tests/divisions/{division}` | Ответ |
| --- | --- | --- |
| GET/POST | `/external-tests` | Каталог с пагинацией / созданный ExternalTest |
| GET/PUT | `/external-tests/{external}` | ExternalTest / изменённый ExternalTest |
| GET | `/external-tests/{external}/results` | `items:ExternalResult[],total,limit,offset` |
| PUT/DELETE | `/external-tests/{external}/results/{account}` | Обновлённый ExternalTest |
| GET | `/external-tests/{external}/history` | Выбранная история с пагинацией |
| GET | `/external-tests/{external}/delete-preview` | `test,results_count,confirmation_token,expires_at` |
| DELETE | `/external-tests/{external}` | `test_id,results_deleted` |
| GET | `/external-results` | `items:[{test,result}],total,limit,offset` |

Создание: `{name,direction_id,date}`; дата `YYYY-MM-DD`. Обязателен `Idempotency-Key` 16–128 символов. Редактирование добавляет `expected_revision`. Ручная коррекция передаёт `expected_revision`, `expected_result_revision` (0 для отсутствующей строки), явный `score` и `Idempotency-Key`. Удаление строки передаёт обе ревизии и ключ. Балл — конечное число 0–100, дробные значения сохраняются. `score:null` — новое явно неизвестное значение; пропущенный `score` в PUT запрещён. Импорт по прежней логике требует числовой процент, null не импортируется.

Удаление теста требует токен из preview и показанную ревизию. Токен действует десять минут, связан с организацией, подразделением, тестом, ревизией и актором. Удаление логическое: каталог и рейтинг перестают видеть запись, история и квитанции сохраняются. Устаревшее подтверждение после изменения оценки или реквизитов не действует.

Основные ошибки: `access_denied` 403; чужой/удалённый объект `not_found` 404; `stale_revision`, `stale_result_revision`, `idempotency_conflict`, `delete_confirmation_mismatch` 409; `external_score_required`/`invalid_external_score` 400; недоступная зависимость 503. Полная схема доступна через `/openapi.json`.

## Хранение и повторы

`tests_external_catalog_v1` — агрегат каталога, текущих результатов, квитанций команд и выбранных ID истории. `tests_external_versions_v1` — неизменяемые изменения реквизитов и оценок. Сохранение всех строк импорта, квитанции и указателя на историю выполняется одним CAS по организации, подразделению и ревизии. Неуспешный CAS не публикует историю или частично записанные баллы; возможная неизбранная запись истории не выдаётся API.

Все три внешние коллекции, включая `tests_external_domain_v1`, объявлены в `dev/schema/mongo-extensions.json`. `services/tests/scripts/dev_setup.py` регистрирует только Tests-owned имена, читая актуальный файл под общим `fcntl` lock и сохраняя декларации соседей; повторная регистрация не меняет файл. Helper создаёт коллекции при штатном setup, но marker готовности создаёт только Go startup после инициализации домена. Исправление декларации не потребовало записей в БД, изменения индексов или перезапуска runtime.

Результаты ограничены 2000 учениками на тест и 15 MiB на агрегат. Вход импорта ограничен 5000 исходными строками и общим HTTP телом 1 MiB. Ограничения завершают весь пакет ошибкой, автоматического разбиения с частичным применением нет. Проигравшая конкурентная доставка той же ручной команды проверяет квитанцию победителя; повтор удаления проверяет точную ревизию tombstone и исходный токен. Чужая команда, иной payload или более поздняя ревизия сохраняют конфликт.

В старом коде отсутствовали редактирование реквизитов, ручные коррекции, ревизии и история внешних результатов; здесь это отдельные новые административные возможности. Существующие правила импорта и формула рейтинга не заменены новой системой оценивания.

## Соседние владельцы

- [Uploads контракт](../external-import-contract.md): сервис хранит файл, preview-сессию и job. Tests сопоставляет ФИО/аккаунты, проверяет все строки и подтверждает пакет. Internal validate/commit требуют служебный ключ и действующую пользовательскую авторизацию; один ключ не предоставляет права пользователя. Поддержка нового фонового Auth grant допускается только после согласованного Auth контракта.
- Core предоставляет `POST /internal/core/test-references` с `include_students:true`, одним подразделением, полной проекцией `account_id/profile_id/full_name/is_active`, `accounts_complete:true` и `account_projection_version:1`. Неполный или чужой ответ закрывает запись ошибкой. Tests не читает и не изменяет Core DB.
- [Рейтинг и готовность](external-readiness-contract.md): snapshot содержит реальный внешний каталог/результаты, версии и `external_domain`. Отсутствующий marker или повреждённый домен дают 503. Исправный пустой каталог отличается от отсутствующего домена. Согласованная актуальность проверяется повторным HTTP snapshot/hash; новый внешний Rabbit outbox без согласованного consumer не вводится.
- [Кэш и общий каталог](../cache.md): права и доступ к сдаче живые; BFF получает каталог и доступность одним owner запросом.
- [BFF подготовленные компоненты](../../bff/external-tests-integration.md): интеграцию и изменение общего UI выполняет чат BFF. Feature flag остаётся выключенным до совместной HTTP/UI приёмки.

## Проверка

Go тесты проверяют scope, живую авторизацию, нулевые/дробные/неизвестные баллы, подтверждение удаления, атомарный CAS, импорты, кэш и snapshot readiness. Реальная HTTP проверка — `services/tests/scripts/external_integration_test.py`, с отдельными синтетическими фикстурами двух организаций и нескольких подразделений. Результаты запуска и идентификаторы фиксируются в `dev/local/external-tests-integration-summary.json`; наличие этого скрипта не является подтверждением его успешного запуска.
