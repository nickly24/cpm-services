# Готовность внешних тестов в снимке рейтинга

`POST /internal/tests/ratings/snapshot` возвращает явный статус внешнего домена:

```json
{
  "external_domain": {
    "schema_version": 1,
    "status": "ready",
    "organization_id": 11,
    "division_id": 17
  }
}
```

Это обязательный объект успешного снимка, не nullable и не резервное значение.
Организация и подразделение совпадают с проверенной областью запроса и всего
снимка. Статус добавляется после успешного чтения и проверки внешнего источника;
пустой готовый каталог сохраняет `external_tests:[]` и полноценную версию.

Перед чтением каталога Mongo-адаптер проверяет принадлежащий Tests marker
`tests_external_domain_v1`, `_id:"external-tests"`. Владелец записывает
`schema_version:1`, `status:"ready"` после успешной инициализации предметных
коллекций и индексов. Отсутствие marker, другое состояние/версия, повреждённые
поля и ошибка его чтения дают `503 external_domain_unavailable`. Ответ ошибки
не содержит успешного `external_domain`, `external_source_version` или
`input_hash`. Пустая либо отсутствующая коллекция каталога сама по себе не
считается свидетельством готовности бизнес-домена.

Успешный снимок проверяется двумя полными чтениями. Каждое включает каталог
внутренних тестов, официальные сдачи, marker внешнего домена и его каталог.
`external_domain` вместе с его схемой и областью входит в общий SHA-256
`input_hash` наряду с `tests`, `external_tests` и `external_source_version`.
Внешняя версия учитывает каталог, результаты и их ревизии; время запроса в хеш
не входит. Изменение между чтениями возвращает 409, а не смешанный снимок.

Внутренний `ExternalDomainStatus` и `makeExternalDomainStatus(org, division)`
переиспользуются контроллерами владельца. Сам конструктор DTO не проверяет
готовность: контроллер должен сначала выполнить `externalDomainReady` и
проверить пользовательскую область. Сервисный снимок дополнительно проверяет
организацию, подразделение и направления через Core.
